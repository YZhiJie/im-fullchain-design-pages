第 1 幕
🕳️ Gap 检测 — 找出"消失"的消息

Gap 是什么？serverSeq 应该连续 1,2,3,4... 如果收到 1,3,4 → 缺失了 2，这就是 Gap。

怎么检测？离线同步后遍历本地消息的 serverSeq，检查是否连续。Gap 范围就是 [prev+1, curr-1]。

怎么补？精确请求服务端：GET /sync?convId=xxx&fromSeq=2&toSeq=2

第 2 幕
📤 分片上传 + 断点续传

原理：大文件切成 2MB 分片，并发上传。每个分片独立，失败了不影响其他。

断点恢复：每个分片上传后记录到本地 SQLite。断网了不怕，恢复时查服务端已上传哪些，只传缺失的。

秒传：上传前算 MD5 → 服务端查是否已有相同文件 → 有就直接用，跳过上传。

第 3 幕
🛡️ 多层兜底 — Gap Sync 失败了怎么办？

Gap Sync 本身也会失败（网络持续抖动）。所以设计了 4 层递进兜底，越往后越"慢"但越"稳"：

Layer 1 → 立即重试 · Layer 2 → 指数退避 1s→3s→8s→16s · Layer 3 → 下次重连自动重放 · Layer 4 → UI 提示用户手动重试

效果：Gap 最终补全率从 88% 提升到 99.2%。

🎯 离线补偿核心总结

  • Gap 检测 = serverSeq 连续性检查：缺失区间 [prev+1, curr-1]，精确拉取补全
  • 断点续传 = 分片 + 持久化 + 服务端查询：断网不丢进度
  • 秒传 = MD5 预检：团队内重复发送文件命中率 42%
  • 弱网 5 档适配：并发降级 + 退避策略调整
  • 自愈恢复：启动时比对本地 vs 服务端会话 checkpoint
