第 2 幕
📦 Outbox 模式 — 消息的"安全出口"

1Outbox 是什么？一个发件箱——消息先写进来，然后才发出去。没有 Outbox 的 IM = 寄信没写收件人。

2为什么要它？App 被杀进程、网络断了、服务端抖动——Outbox 让消息"不丢不重"。注意消息卡片飞向服务端的动画。

3三种状态：🟡 sending → 🟢 sent → 泄漏则 🔴 failed。

第 3 幕
🔀 乱序容错实验台 — 亲手制造一次乱序

1规则：排序永远以 serverSeq 为准。迟到的消息如果离左右邻居 seq 差 ≤ 3 或 时间差 ≤ 500ms，判定为「短暂乱序」→ 自动滑入正确位置。

2动手试：按 1 → 2 → 3 → 6 投递，再投 4，看它如何被自动修正；换成 1 → 2 → 10 再投 6，看看会怎样。

3为什么要有阈值？小抖动自动修正保证流畅；差异过大则说明可能真丢消息了，交给离线补偿的 Gap Sync 处理，不要凭空猜测。

核心要点
🎯 核心经验总结

🎯 三句话记住消息时序

  • 三层时序：clientSeq 保证本地顺序 → serverSeq 权威裁决（跨端一致） → 渲染重排 渐进体验
  • Outbox 是必须的：先落盘再发送，进程被杀 / 断网都能恢复，配合幂等去重实现"效果上的 Exactly Once"
  • 阈值化乱序修正：小抖动（seq 差 ≤ 3 或 时间差 ≤ 500ms）自动修正；大差异交给离线补偿 Gap Sync，绝不凭空猜测
